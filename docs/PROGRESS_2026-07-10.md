### 2. Full UI redesign — accessibility-first (every page, every view)
New token-based design system (`src/styles/theme.css` + `DESIGN_SYSTEM.md`):
- **Themes:** light + dark (system-aware toggle) + high-contrast mode — all WCAG 2.1 AA contrast-checked
- **Accessibility settings panel** on every layout: text size (4 steps), high contrast, reduced motion, theme, language (en/ar)
- **UI kit** (`src/components/ui/`): Button, Card, Badge, Field (Input/Select/Textarea), Modal (focus trap), PageHeader, StatCard, EmptyState, Loading/Skeleton, LiveRegion (screen-reader announcements), SettingsPanel
- **Role accent colors:** hospital teal, police indigo, civil defense orange, firefighter red, admin violet, patient blue
- **Icons:** lucide-react everywhere (all emojis/inline SVGs removed); bundled Inter + Noto Sans Arabic fonts (offline-first)
- **A11y:** skip links, aria-current/pressed/expanded, 44px+ touch targets (56–72px on phone views), visible focus rings, RTL logical properties, icon+text (never color alone)

Restyled: Login/Register, all 5 patient pages + 11 SOS chat components + 6 news components, all 9 hospital/department dashboard pages, all 4 admin pages, all 16 responder pages + 6 responder components, 3 map components, charts, shared widgets, 3 app layouts. Responder unit tests kept green (66/66).

### 4. Security review + hardening (backend)
Full report in `backend/SECURITY_REVIEW.md`. Fixed: weak dev-secret fallbacks (boot refusal in prod), session invalidation (jti revocation + logout/revoke endpoints), production rate limiting (per-IP/per-user, strict auth buckets, 429+Retry-After), python-jose CVE bump, login timing-oracle, AES-CBC→AES-256-GCM for medical data, GDPR **right-to-erasure** + **data export** endpoints (`routes/privacy.py`), audit-log pseudonymization. **Critical handoffs (need team action):** unauthenticated Socket.IO rooms leak patient location/medical data (`websocket/handler.py`); real Telegram API credentials committed in `.env.example` — rotate + purge history.

### 5. Features completed (FEATURES.md gaps)
- **Module 1 — Patient registration (was Critical):** full 7-step wizard (account → location → medical → special needs/living situation → emergency contacts → GDPR consent → review), wired to real API (`POST /patients` → login → profile enrichment), per-field API error mapping, 145 new i18n keys (en+ar). OTP (1.1) still needs a backend SMS provider.
